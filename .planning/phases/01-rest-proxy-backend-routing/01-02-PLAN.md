<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Splunk platform → app handler | restmap.conf is the single registration point where authenticated session state is handed to our Python code |
| Filesystem → handler | settings.json is read each process lifetime; attacker with write access to `local/settings.json` could weaken allowlist |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T2-01-AuthBypass | Spoofing | REST registration | mitigate | `requireAuthentication = true` explicitly set in `[script:...]` stanza (D-04, S-12 reinforcement) — dashboard iframe carries Splunk session cookie; anonymous callers get 401 from Splunk before reaching handler |
| T2-02-WrongStanza | Configuration error | restmap.conf syntax | mitigate | Use `[script:<name>]` NOT `[route:...]` (audit A-04, Pitfall 1). Validated by presence-grep in acceptance criteria |
| T2-03-Python2Fallback | Tampering | python version | mitigate | `python.version = python3` explicitly declared (audit A-13, Pitfall 3); without this Splunk 8.x can fall back to Python 2 and `urllib.parse`/`ipaddress` imports fail |
| T2-04-AllowlistWeakening | Tampering | local/settings.json | accept | Users editing `local/settings.json` is an intended operation (D-01 explicitly documents extension). File system permissions + AppCert scope protect against unauthorized edits. Defense-in-depth via `_validate_url` runs regardless of allowlist — SSRF IP-block layer (T1-01 layer d) still blocks private IPs even if user adds them to allowlist |
| T2-05-MissingFromPackage | Availability | release packaging | mitigate | `build_release.sh` and `deploy.sh` updated to include `bin/` + `default/restmap.conf` + `default/settings.json`; verification criteria include `tar -tzf` listing of resulting package |
| T2-06-SystemFileWrite | Integrity | AppCert compliance | mitigate | All config files scoped to `default/` within the app; no `$SPLUNK_HOME/etc/system/` modifications, no `web.conf` touches (code_context constraint — AppCert compliance) |
</threat_model>
