<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted null-origin iframe → parent `message` event | postMessage data and `event.origin` / `event.source` |
| Parent → Splunk REST tile proxy | Same-origin authenticated GET; server enforces SSRF per Phase 1 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T03-01-01 | Spoofing | `message` handler | mitigate | Accept tile requests only when `event.origin === 'null'` (serialized opaque origin for `about:srcdoc` per D-NN-4); never use `includes`/`startsWith` on origins. |
| T03-01-02 | Tampering | `fetch(url)` | mitigate | Before fetch, require `PROXY_URL_SHAPE.test(url) === true`; else do not fetch and do not reply (**silent drop** per amended DS-AUTH-04 — no `postMessage`; iframe D-06 timeout handles the pending request). |
| T03-01-03 | Info disclosure | postMessage responses | mitigate | Success payload exactly `{ type: 'maps-plus:tile-result', requestId, ok: true, tileData, contentType }`; failure `{ type: 'maps-plus:tile-result', requestId, ok: false, code, httpStatus? }` per D-NN-3 — no tokens or PII. |
| T03-01-04 | DoS | Parent fetch fan-out | mitigate | D-05 fixed window 500/1000 ms keyed on `event.source`; silent drop; one `console.warn('[maps-plus:parent-bridge] rate limit exceeded for iframe origin=' + event.origin)` per breach window. |
| T03-01-05 | Elevation | Authenticated proxy misuse | mitigate | Single URL shape + Phase 1 server allow-list (D-NN-5); bridge never implements a second host policy. |
| T03-01-06 | Tampering | Message type confusion | mitigate | Switch on `data.type` with exactly four literals `maps-plus:fetch-tile`, `maps-plus:tile-result`, `maps-plus:ping`, `maps-plus:pong`; default branch returns without network I/O (D-NN-2). |
</threat_model>

    Handler logic (concrete values):
    - Read `var expectedTopOrigin = window.location.origin` for logging only; **incoming** tile requests validate `event.origin === 'null'` (exact string — D-NN-4 for serialized opaque origin from DS `about:srcdoc`).

Iframe-side D-06 **8000ms** per-request timeout absorbs the pending request as `{ ok: false, code: 'timeout' }` / blank tile.)

If `!entry || now - entry.windowStart >= 1000` reset `{ windowStart: now, count: 1, warned: false }`. Else increment `count`; if `entry.count > 500` and `!entry.warned`, set `entry.warned = true` and `console.warn('[maps-plus:parent-bridge] rate limit exceeded for iframe origin=' + event.origin)` once per window; if `entry.count > 500` return without fetch/postMessage. On every rate check, delete any map entries where `now - e.windowStart > 60000`.

    - Wrap `fetch` in `try/catch`; on throw, postMessage `{ ok: false, code: 'fetch_failed' }` with same outer fields.
