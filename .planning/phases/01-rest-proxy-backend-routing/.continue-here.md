# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: **Offline verification cannot catch splunkd-integration bugs.** Every UAT failure so far (UAT-1 through UAT-5b) was invisible to grep-based config checks and offline unittest stubs. Before declaring any Splunk REST handler "done" in the future, the phase MUST include at least one live-splunkd smoke test (docker-based is fine).
- [ ] CONSTRAINT: **Splunk's persist framework cannot return raw binary payloads.** It JSON-serializes `handle()`'s return dict end-to-end, and splunkd transcodes the payload string as UTF-8 on the HTTP wire. Latin-1 round-trip survives the Python→JSON pipe but still gets corrupted by splunkd's HTTP body writer. If we ever go back to persist, the only path is base64 + Phase-2 JS client decode.

**Do not proceed until all boxes are checked.**

### UAT-4 — chose BaseRestHandler (Option A) over persist+base64 (Option B)
**Why:** Simpler; server-only; no JS coupling; native binary; browser HTTP cache makes the subprocess overhead invisible (~50ms/cold-tile, ~0ms/warm-from-browser).
**Reversible?** Yes — all persist-era commits preserved in git (ec167a1, 7a422d5, da60f26). `git revert` or cherry-pick could resurrect Option B if UAT-5b proves unfixable.

### UAT-5 — flattened bin/ layout
**Why:** Splunk's `runScript.py` chdir'd into a relative path that didn't exist. Single-handler app → no need for namespace packages.
**Reversible?** Yes — `git mv` is trivial to undo. BUT new symptom UAT-5b (empty scriptDir) suggests the flattening itself may not be the right answer. Maybe `script =` needs an absolute path format.
